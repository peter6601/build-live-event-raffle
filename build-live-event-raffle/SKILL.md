# 搭建現場互動抽獎網站

## 先確定現場規則

從需求取出參加單位（座位、隊伍或個人）、加入方式、基本票數、加油規則、倒數、抽幾位，以及缺席怎麼處理。新專案可先採用以下預設，並在交付時列出所採用的規則。

- 手機掃公開 QR，免登入、免填姓名，選一個參加單位。選座位代表支持對象。若需求是個人抽獎，先確定辨識或發券方式。
- 每個開放候選先有一票，倒數內每次有效手動點擊加一票。長按只是一個操作。預設 30 秒，主持人可在開始前調整。
- 截止時凍結候選與票數。主持人一次抽一位。已抽到的候選退出抽獎池。缺席時保留作廢紀錄，由主持人另按補抽。
- 把「同一候選可以多人支持」與「一人一票」視為不同的規則。若活動要求一人一票，使用可核對的身份或單次入場憑證。免登入的加油模式只承諾上述計票規則。

## 先做出三個可走通的畫面

| 畫面 | 最小流程 |
| --- | --- |
| 賓客手機 | 選擇支持對象 → 等待開始 → 點擊加油 → 等待揭曉 |
| 現場投影 | 加入 QR → 倒數與公開加油狀態 → 揭曉與得獎紀錄 |
| 主持控制 | 設定資格與倒數 → 開始 → 截止後抽出 → 作廢／補抽 |

沿用專案已有的框架、資料庫與測試方式。全新小型版本可用靜態前端、單一 HTTP 服務與持久資料庫，先用輪詢同步。已有 PostgreSQL 時，讓本機彩排沿用正式規則與 SQL。將公開場次快照和主持寫入分開，主持權限在伺服器驗證，憑證存於伺服器環境。QR 指向可用手機開啟的賓客網址。

## 讓伺服器決定計票和抽獎

1. 以伺服器時間及場次狀態驗證加油。每筆請求帶場次、輪次、點擊時的支持對象與唯一操作 ID。重送沿用同一 ID，回傳同一結果。計票與截止用交易或等效機制排序，避免截止快照漏票、重複計票或收到上一輪的遲到請求。手機可立即顯示按壓回饋，票數跟隨伺服器確認。
2. 在抽獎交易內讀取鎖定且尚未抽中的候選，使用安全、無偏的整數隨機值，從總權重區間取樣並依累積權重找到候選。每次抽獎也帶操作 ID，原子保存結果及排除得獎者。同一 ID 重送時回傳原抽獎。交易內也要檢查揭曉是否仍在進行、是否已達本輪得獎人數上限。即使連按送出不同 ID，也只能在狀態允許下一抽時建立新結果。
3. 投影依伺服器提供的揭曉時序播放拉霸或靜態等待。用伺服器控制公開結果的時機，避免公開快照在揭曉前送出得獎者或可推回得獎者的終點。刷新後讀取同一抽的狀態。若已公布缺席作廢，保留原紀錄並維持該候選排除。

## 用完整彩排驗證

- 在手機與投影實際走完一次。測倒數前後、兩台同時幫同一座位、重送、切換對象與截止鎖定。以可控制的隨機輸入測試權重區間兩端。
- 抽獎時連按、刷新投影與重新連線，確認結果一致，公開畫面依揭曉時序更新。再演練缺席補抽，檢查沒有重複得獎。
- 本機彩排請用手機可達的區網位址和獨立測試場次。正式場次使用已設定的 HTTPS 網址與持久資料庫。部署若在任務範圍內，用實際公開 QR 和獨立彩排場次重跑手機、投影、主持三端，再回報驗證結果。

交付時附啟動方式、三個畫面的入口、採用的抽獎規則，以及主持人可照著操作的彩排步驟。
